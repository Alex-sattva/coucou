Product decisions (locked)

  1. Placement: replaces the closed (compact) island and the expanded home. The panel also takes over .approval, .question, .error and .finished. Every other view ships unchanged.
  2. One Mochi per agent session, keyed by session_id, including Claude Code in a plain terminal. Several approvals can wait at once.
  3. Main spot order: clicked agent, then oldest agent that needs you, then the agent of the front window's workspace, then the previous main, then the most recently active.
  4. Quiet by default: the panel opens on its own only for needs-you, blocked or done. You can also summon it with a click on the notch or ⌃⌥Space.
  5. Bar: answers the main agent, and starts new OpenCode tasks in its folder. It can't start Claude Code.
  6. Voice: hold ⌥ alone to talk, using on-device speech. Releasing sends.
  7. Motion: the particle hand-off. Only the main Mochi travels; small Mochis recolour.
  8. Interface copy is English.

Pure logic goes in standalone files with no AppKit or SwiftUI imports, tested with the repo's swiftc script pattern.

Reuse: BotEngine, HarnessMochiView (colour, hop, pause), HarnessMotion constants, the pill-flight technique, IslandShape, openSpring/closeEase, FileDiff, AskQuestion, OpenCodeChat.run, the WindowContextCapture AX read, and HotKeyCenter.

Step 1 · Session model (pure, tested)

The reducer maps each event to a phase:

  • prompt → thinking
  • toolStart → working (steps capped at 40)
  • toolFailed → working, with a "⚠" step
  • approvalRequested → approval
  • questionAsked → question
  • a notification mentioning "rate limit" → blocked
  • a notification ending in "?" → question
  • stop → finished, unseen
  • stopFailure → blocked
  • interrupt → idle
  • end → removed

attentionAt is set when a session enters a needs-you phase. An unknown session id creates the session.

Account forTwo sessions in the same folder stay separate. end on an unknown session does nothing. prune never removes a session that is holding an approval or question.

Acceptancebash scripts/test-agent-session.sh exits 0.

Step 2 · Picker, attention queue, slot order (pure, tested)

The picker follows decision 3. Within the context workspace, the latest lastEventAt wins.

The slot order keeps every surviving sub in its slot. If the new main was a sub and the old main is still alive, the old main takes the new main's slot, and that index is returned for recolouring.

Account forNo sessions; a selected session that died; ties on attentionAt; the main session dying, in which case the gap closes with no recolour.

Acceptancebash scripts/test-assistant-logic.sh exits 0.

Step 3 · Feed sessions from HookServer

Every event with a session_id goes into AppState.sessionStore. This happens before the pill routing's early return, so plain terminals count too.

  • The kind comes from coucou_agent or the Cursor bundle id. Anything else is Claude Code.
  • The colour comes from IslandConst.colorForProject.
  • Diffs are also stored per session in sessionFileDiffs.
  • Sessions idle for 15 min are pruned by a timer that only runs while sessions exist.

Blast radiusPill behaviour (VS Code, Cursor, Codex, external) must not change.

Account forGemini and Antigravity events arrive already normalised. OpenCode's Stop has no final line. Events without a session_id are ignored.

AcceptanceThe build succeeds. Run a plain-Terminal claude session: the log shows thinking → working → finished. A VS Code session at the same time appears as a second session, and its pill is unchanged.

Step 5 · What the user is working on

The tracker reacts to app activation, plus an AXObserver for focused-window and title changes. It reads the focused window title, matches it to a live session's workspace, and publishes the result after a 1.0 s dwell. It never polls.

Account forNo Accessibility permission, or the APPSTORE build: the result is nil and the picker falls through. The observer is removed when there are no sessions or the island is hidden. Coucou's own windows are ignored. Matching is by whole path component, longest first, so app doesn't match app-web. Path-like terminal titles are matched too.

Acceptancebash scripts/test-title-matcher.sh exits 0. Switching between Ghostty on A and VS Code on B moves the context about 1 s after each switch.

Step 6 · The quiet strip (replaces compact)

In compact mode, the main Mochi sits left of the camera and the sub slots sit right of it, replacing BotPlacement's compact Mochi and CompactMiniGrid.

  • Main: the resting diameter × 1.25, capped at the notch height − 4. Its centre is 30 pt outside the notch's left edge.
  • Subs: about 0.68 × the main diameter, spaced 26 pt, starting 22 pt right of the notch. At most 5 are shown, then a +N.
  • Width: the notch width + 2 × max(56, subs × 26 + 26), so the island stays symmetric.
  • Status dots: amber for approval or question, red for blocked, green for finished and unseen.

The main Mochi is one view instance alive in both modes, wrapping HarnessMochiView. The slot Mochis use a wrapper whose colour can change, instead of editing MiniBotCanvasView.

Account forEvery timeline pauses when hidden. Macs without a notch use the same layout around the virtual notch. Clicking a sub selects it and opens the panel.

AcceptanceThree sessions show as one main and two subs. Main follows the focused window within about 1 s. With no sessions, the island is hidden.

Step 7 · The panel

.overview, .approval, .question, .error and .finished all route to AssistantPanelView. It is 640 wide, uses the existing expanded corner, and has a height per content, pinned in AssistantMetrics.

The top row holds the main Mochi (48 pt) at (40, 64), the task line, the agent chip and the mic. Under it is the need card:

NeedCard
approval"N steps done", then "Can I run cmd?" with Deny and Allow ⏎. Keep "Always" if today's view has it.
questionThe AskQuestion options, plus free text if the question allows it.
blocked"I hit an error I can't get past on my own.", the error in mono, and Open in terminal. There is no Try again.
finishedThe final line, or "Done.", the files with +/− counts, Open diff and Got it.
summoned, nothing pendingThe bar row only.

Open rules:

  • The panel is open if it was summoned, if a Mochi was selected, or if there's a need whose signature isn't the dismissed one.
  • Esc dismisses it. A new need reopens it.
  • A finished card folds after 8 s unless it's hovered or the bar has focus.
  • Hover no longer expands the island. A click or ⌃⌥Space summons it.
  • Approvals hold the island open, as they do today.

Account forNeeds are queued in order. Timeouts remove their card. ⏎ only works on a visible approval. Only one card shows at a time.

AcceptanceThe panel opens on A's approval. B's done card waits until A is answered. Esc hides the panel and a new need reopens it. The done card folds after 8 s.

Step 8 · Motion: the particle hand-off

When the main changes from X to Y:

  1. If Y was a sub, a dot flies from Y's slot to the main Mochi. It takes 0.95 s: 62 % is travel with a cubic ease-out, shrinking from 9 to 4 pt with a fading halo. Then 14 dots burst out to a 26 pt radius.
  2. At flight start: the main colour starts blending X → Y over about 0.6 s, the wash switches colour over 0.6 s, and the text blur-swaps over 0.32 s.
  3. At landing: the main Mochi hops in place, using hopPose for 0.9 s.
  4. After landing: Y's slot, which never moved, recolours to X.

If Y wasn't a sub, there's no flight: the colour changes and the Mochi hops.

Wash: a radial gradient centred on the main Mochi at (40, 64), radius about 70 % × 120 % of the panel, opacity 0.34, fading to clear at 70 %. It only shows while expanded.

Strip ↔ panel: only the main Mochi travels, using timingCurve(0.25, 0.8, 0.25, 1, 0.35). Subs stay in the strip and fade over 0.2 s, never sliding. The island shape keeps its spring and ease.

Account forA second hand-off starting mid-flight; a hand-off while hidden, which just applies the end state; the overlay being unmounted when idle.

AcceptanceClicking a sub plays the dot, the blend during flight and the hop on landing, and the clicked slot becomes the old main. Nothing else moves. A context switch and an approval elevation play the same hand-off.

Step 11 · Voice: hold ⌥ to talk

Use SFSpeechRecognizer on-device with an AVAudioEngine tap, and stream partial results into the bar.

  • Listening starts after ⌥ alone has been held for 300 ms. Any other key cancels, so ⌥-shortcuts keep working.
  • Releasing sends the transcript. Esc cancels.
  • Add the mic and speech usage strings to project.yml, plus the audio-input entitlement if the app is sandboxed. Commit the regenerated Info.plist.

Account forPermission denied, or no on-device recogniser: show a one-line notice. The engine and tap are stopped on every exit path. Audio never leaves the Mac.

AcceptanceHold, speak and release: an OpenCode task starts. ⌃⌥Space still works. CPU is back to about 0 % within 5 s.

Out of scope / Do NOT
